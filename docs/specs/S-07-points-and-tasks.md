# S-07.2／S-07.4 點數帳本、任務與兌換規格

> **狀態：已確認（2026-10-12）。** 涵蓋 S-07.2（點數發放、扣除與防重複）與 S-07.4（任務週期、兌換項目與管理員定價）。標為**待確認**的項目不得在實作中自行假設。決策摘要見 [`decisions.md`](decisions.md) 的 S-07 一節。

## 1. 名稱與範圍

- 點數正式名稱：**思辨點數**（英文 `Points`）。程式、資料表與欄位一律用 `points`，名稱只影響介面文案（三種語言各自翻譯）。
- 點數用途只有兩種：解鎖角色部件（F-17.2）與兌換（F-19.4）。本期兌換項目只有角色部件，兌換與部件解鎖是同一個「購買」流程，不另設第二種商品。
- 不納入教材觀看獎勵（S-07.5）。

## 2. 點數帳本（S-07.2）

### 2.1 資料模型

- `point_ledger` 只新增、不修改、不刪除（帳號刪除除外，見 2.5）。每筆記錄：`user_id`、`delta`（整數，正為入帳、負為扣除）、`reason`、`source_type`、`source_id`、`unit_price`（僅扣除時記錄當時實際價格）、`created_at`。
- `reason` 與 `source_type` 的值：

| `source_type` | 說明 | `source_id` |
| --- | --- | --- |
| `conversation` | 完成對話發點 | 對話 ID |
| `achievement` | 解鎖成就發點（數值由 S-07.3 定） | 成就 ID |
| `task` | 任務領取 | `<task_id>:<period_start>` |
| `purchase` | 部件解鎖／兌換扣點 | 部件 ID |
| `admin_adjustment` | 管理者手動調整 | 該次調整的唯一 ID |

- **防重複由資料庫保證**：`(user_id, source_type, source_id)` 加 UNIQUE 約束。同一事件重複送出時，第二次入帳因違反約束而不寫入，API 對呼叫端視為成功（冪等），不回傳錯誤。
- **欄位之間的一致性由資料庫保證**（CHECK 約束）：`purchase` 必須記錄 `unit_price`，且 `delta = -unit_price`（免費部件兩者皆為 0）；其他來源不得記錄 `unit_price`，且 `delta` 不得為 0。`admin_adjustment` 可正可負（2.4）。
- **`source_id` 不做成指向 `conversations` 的外鍵**，對話被刪除後帳本紀錄仍保留。
- 餘額＝帳本 `delta` 加總；可另存快取欄位加速讀取，但以帳本為準。
- 帳本與日誌只存 ID 與數值，不含對話內容或任何敏感欄位（S-02.2）。

### 2.2 發放規則

- **完成對話**：每場發 **10 點**。「完成」沿用 S-03.3：該場已產生 AI 總結（達到收斂條件，或第 20 回合強制結束）。未產生總結的對話不發點。
- **不設每日上限**：學生一天完成幾場就發幾場的點數。
- **解鎖成就**：成就解鎖當下入帳，點數數值由 S-07.3 決定。
- 入帳與觸發它的事件（總結寫入、成就解鎖）應在同一個資料庫交易內，或可由事件重試補發；重試不會造成重複（2.1 的 UNIQUE 約束）。

### 2.3 扣除規則

- 只有兩種扣除：部件解鎖與兌換，皆寫入 `source_type='purchase'`。
- 扣除與餘額檢查在同一個交易內，鎖住該使用者（`SELECT ... FOR UPDATE`），避免兩個並行請求重複花用同一筆餘額。
- **餘額不得為負**：點數不足時購買失敗，不寫任何帳本紀錄，也不改變部件擁有狀態。
- 扣除金額為購買當下的價格，並記錄在 `unit_price`。

### 2.4 管理者手動調整

- 本期不做管理介面；管理者直接操作資料庫，新增一筆 `source_type='admin_adjustment'` 的帳本紀錄（`delta` 可正可負）。
- 每次調整必須同時寫一筆稽核紀錄：操作者、時間、對象學生、`delta`、原因說明。稽核紀錄不含對話內容。維運流程與資料庫存取紀錄的要求見 [`S-09.3-ops-procedures.md`](S-09.3-ops-procedures.md) 與 S-02.1。
- 調整後餘額不得為負；會使餘額為負的調整不得執行。
- 調整不得修改或刪除既有帳本紀錄，要更正就新增一筆反向調整。

### 2.5 邊界情境

- **學生刪除已得點的對話（S-02.5 允許）：不追回點數。** 帳本紀錄保留，餘額不變。
- **帳號刪除（F-22.5）：** 該帳號的帳本與擁有紀錄一併刪除。
- **移出修課名單／停用帳號：** 點數與帳本保留，重新加回或復原後照舊（比照 S-01.3）。
- **可見範圍：** 學生只能查看自己的**餘額**，看不到帳本明細（點數不是真錢，不需要呈現收支；帳本仍完整保存在後端，供防重複、稽核與追查）。API 不提供查詢他人點數的路徑，教師（含助教）看不到學生的點數與帳本。

## 3. 任務（S-07.4）

### 3.1 週期

- 有**每日任務**與**每週任務**兩種。
- 時區固定為 **Asia/Taipei**。每日週期為當天 00:00 至 24:00；每週週期為週一 00:00 至週日 24:00。週期結束後自動進入新週期，進度重新計算。
- 每個週期以 `period_start`（該週期起點）識別。

### 3.2 任務內容

- 任務條件型別由程式內建，本期只有「週期內完成 N 場對話」一種。管理員可調整的只有各任務的**目標數 N** 與**獎勵點數**，不能自訂條件邏輯。
- 進度以**完成事件**計算：每場對話在完成（定義同 2.2，已產生 AI 總結）時記錄一次完成事件，內容只有學生、對話 ID 與完成時間，不含對話內容；同一場對話只記一次。進度為該週期內完成事件的數量，依完成時間歸屬週期。
- **完成事件不依賴對話是否仍存在**：學生刪除對話後事件保留，尚未領取的任務進度不減少（與 2.5 刪除對話不追回點數一致）。完成事件不做成指向 `conversations` 的外鍵；帳號刪除時一併刪除。
- 首批任務（**暫定數值**，上線前可調整，管理員也可事後修改）：

| 任務 | 週期 | 目標 | 獎勵 |
| --- | --- | --- | --- |
| 每日對話 | 每日 | 完成 1 場對話 | 5 點 |
| 每週對話 | 每週 | 完成 5 場對話 | 20 點 |

### 3.3 領取

- 達成目標後，學生**手動按「領取」**才入帳；不自動發放。
- 同一任務同一週期只能領取一次，由 `(user_id, 'task', '<task_id>:<period_start>')` 的帳本 UNIQUE 約束保證，與 2.1 同一套機制。重複領取遭拒絕。
- **未領取的獎勵在週期結束後失效**，不能補領。
- 未達成目標時領取遭拒絕，不寫帳本。

## 4. 兌換與部件解鎖（S-07.4）

- 本期可兌換項目只有角色部件（部件清單與素材見 S-07.1，尚未決定）。每個部件有：素材、狀態（啟用／停用）、價格（點數）。
- 解鎖是**永久且不可退款**的。已解鎖者不受之後的調價、停用影響，也不補差額。
- 部件已停用：未擁有者無法解鎖；已擁有者仍可使用。
- 同一部件對同一學生只能解鎖一次；重複解鎖遭拒絕且不扣點（`purchase` 的 `source_id` 為部件 ID，UNIQUE 約束同樣保證）。
- 部件初始價格（**暫定**）：每個部件 **30 點**（約 3 場對話）。S-07.1 部件清單定案後可依部件分別調整，管理員也可事後修改。

## 5. 管理員定價與權限

- 只有**系統管理者**能修改：部件價格、部件啟用／停用、任務的目標數與獎勵點數。教師（含助教）與學生都不行。
- 價格為非負整數；0 點代表免費，允許。
- 調價只影響之後的購買。
- 每次修改寫入稽核日誌（操作者、時間、項目、舊值、新值），做法比照帳號停用、復原與重設密碼（S-01.3）。
- 學生只能替自己的帳號購買，不得替其他帳號解鎖或改寫價格。

## 6. Given / When / Then（供轉成自動化測試）

### 帳本與發放（S-07.2，對應 F-19.1、F-19.2）

1. Given 學生完成一場對話並已產生總結，When 完成事件送出，Then 帳本新增一筆 `+10`（`conversation`，`source_id`＝對話 ID），餘額增加 10。
2. Given 同一場對話已入帳，When 完成事件重複送出，Then 帳本不新增、餘額不變，呼叫端不收到錯誤。
3. Given 兩個相同的完成事件並行送出，When 兩者同時寫入，Then 只有一筆入帳。
4. Given 對話尚未產生總結（中途放棄），When 查詢帳本，Then 沒有該場的入帳。
5. Given 學生一天內完成 5 場對話，When 查詢帳本，Then 有 5 筆各 +10（無每日上限）。
6. Given 成就解鎖，When 解鎖事件送出（含重複送出），Then 依 S-07.3 的數值只入帳一次。
7. Given 學生刪除一場已得點的對話，When 查詢餘額，Then 餘額不變、帳本紀錄仍在。
8. Given 學生，When 嘗試讀取他人的點數或帳本，Then 遭拒絕。
   - Given 教師（含助教），When 嘗試讀取任何學生的點數或帳本，Then 遭拒絕。
   - Given 學生，When 查看自己的點數，Then 只看到餘額，沒有帳本明細。
9. Given 未登入、名單外帳號，When 呼叫點數相關 API，Then 遭拒絕。
10. Given 任何帳本紀錄，When 檢視帳本欄位與日誌，Then 不含對話內容或其他敏感欄位。

### 扣除（對應 F-17.2、F-19.4）

11. Given 餘額足夠，When 解鎖啟用中的部件，Then 帳本新增一筆負數（金額等於當下價格、記錄 `unit_price`），學生擁有該部件。
12. Given 餘額不足，When 解鎖部件，Then 失敗、不扣點、不擁有。
13. Given 部件已停用且學生未擁有，When 解鎖，Then 失敗、不扣點。
14. Given 學生已擁有該部件，When 再次解鎖，Then 遭拒絕、不扣點。
15. Given 餘額剛好夠買一次，When 兩個解鎖請求並行送出，Then 只有一個成功，餘額不為負。
16. Given 部件調價，When 先前已解鎖的學生查看，Then 仍擁有，餘額不變。
17. Given 學生，When 嘗試替其他帳號解鎖，Then 遭拒絕。

### 管理者手動調整

18. Given 管理者直接於資料庫新增 `admin_adjustment` 紀錄，Then 同時存在對應的稽核紀錄（操作者、時間、對象、`delta`、原因）。
19. Given 調整會使餘額為負，Then 不得執行。
20. Given 既有帳本紀錄，When 要更正，Then 以新增反向調整處理，不修改或刪除原紀錄。

### 任務（對應 F-19.3）

21. Given 每日任務目標為 N 場，When 學生當天完成 N 場對話，Then 可領取；領取後帳本新增一筆獎勵（`task`，`source_id`＝`<task_id>:<period_start>`）。
22. Given 已領取，When 同一週期再次領取，Then 遭拒絕、不重複入帳。
23. Given 尚未達標，When 領取，Then 遭拒絕、不寫帳本。
24. Given 週期已結束（跨過 Asia/Taipei 的 00:00，每週為週一 00:00），When 嘗試領取上一個週期未領取的獎勵，Then 遭拒絕。
25. Given 新週期開始，Then 進度重新計算，可再次領取新週期的獎勵。
26. Given 每日與每週任務同時達成，When 分別領取，Then 各入帳一次，互不影響。
27. Given 對話在 23:59 與 00:01 完成（Asia/Taipei），Then 分別歸屬前後兩個每日週期。
28. Given 學生當天完成 N 場對話後刪除其中一場，When 查詢任務進度，Then 進度仍為 N，仍可領取。
29. Given 刪除對話後已達標的任務，When 領取，Then 照常入帳一次。

### 定價與權限（對應 F-19.4）

30. Given 管理者，When 修改部件價格或任務數值，Then 成功，只影響之後的購買，並寫入稽核日誌。
31. Given 教師、學生、未登入、名單外帳號，When 修改價格、啟用狀態或任務數值，Then 遭拒絕。
32. Given 價格為負數或非整數，When 管理者提交，Then 遭拒絕。
