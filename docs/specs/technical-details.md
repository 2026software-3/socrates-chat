## 帳號與名單

### S-01.4 修課名單匯入與移除

**匯入格式**
- 可上傳 CSV 或文字檔，也可以直接貼上；每行一個電子郵件。CSV 可以有 `email` 標題列，也可以沒有。
- 匯入前先去除空白、轉小寫。

**匯入結果**
- 回報新增、已存在（略過）、格式錯誤的筆數，並列出錯誤的行。
- 匯入**只會新增**，不會移除名單上原有但這次檔案沒有的人。移除一律另外操作，避免誤刪。

**移除名單後的資料處理**
- 學生立即失去學生權限，登入後看到「尚未開通」。
- 資料**全部保留**；教師仍然看得到他過去的對話總結。
- 重新加回名單後，恢復存取，資料照舊。
- 要真的刪除資料，改用「刪除學生帳號」（F-22.5）。

## 文字對話

本組依一場對話的進行順序排列：怎麼進行（S-03.2）→ 怎麼結束（S-03.3）→ 出錯怎麼處理（S-03.5）。

### S-03.2 追問準則與難度階段

> 本節屬教學設計，授課教師日後可提出調整；調整時同步更新 S-03.4 的評估情境集。

採用三個階段，依序推進，**不會退回前一階段**：

| 階段 | 目標 | 主要追問類型 | 進入下一階段的條件 |
| --- | --- | --- | --- |
| 1. 釐清 | 讓學生說清楚立場 | 澄清：定義關鍵詞、確認立場 | 學生已表達明確立場，並說明關鍵詞的意思 |
| 2. 論證 | 檢視立場背後的理由 | 理由探詢、假設檢視 | 學生至少提出一個理由，且檢視過一個隱含假設 |
| 3. 挑戰 | 測試立場的韌性 | 反例思考、觀點比較 | 學生回應過至少一個反例或對立觀點 → 符合收斂條件（見 S-03.3） |

**每回合的規則**
- 每次只問**一個**問題。
- 不提出 AI 自己的答案或立場。學生問「你覺得呢？」時，改成反問，或平衡列出不同觀點，但不下結論。
- 語氣中立、尊重，不使用侮辱或威脅的表達（F-07.3）。
- 學生離題時，簡短回應後把話題帶回主題。

**實作方式**
- 對話目前在哪個階段，存在後端資料庫，不交給模型自行記憶。
- 每回合請模型以結構化 JSON 回傳：
  - 本回合的追問類型；
  - 是否達到進入下一階段的條件，以及判斷理由。
- 後端依回傳內容更新階段，並把目前階段放進下一回合的提示。
- 這組規則的版本號記錄在每則 AI 回覆上，方便依 S-03.4 做評估與比較。

### S-03.3 對話回合上限

| 項目 | 規格 |
| --- | --- |
| 回合定義 | 學生送出一則訊息算 1 回合 |
| 引導收尾 | 第 15 回合起，AI 開始引導學生整理結論 |
| 上限 | 第 20 回合時，AI 不再追問，直接產生總結並結束對話 |
| 設定方式 | 全系統一個數值，以環境變數設定；不做成每個活動可調 |
| 學生主動結束 | 任何時候都可以 |

### S-03.5 AI 呼叫逾時

| 項目 | 規格 |
| --- | --- |
| 首個 token 逾時 | 15 秒內沒有收到任何串流內容，就視為失敗 |
| 完整回覆上限 | 60 秒；超過就中斷 |
| 自動重試 | 只在**尚未串流出任何內容**時重試 1 次；已經串流到一半才失敗，不自動重試 |
| 串流中途失敗 | 捨棄已產生的部分內容，這則 AI 回覆標記為失敗，顯示「AI 暫時無法回覆」與重試按鈕 |
| 使用者最久等待 | 約 30 秒（15 秒 × 2 次）就會看到錯誤，不會無止盡等待 |

「中途失敗不自動重試」是為了避免同一段回覆在畫面上出現兩次。

## 語音

本組先寫正常流程（S-05.2），再寫改用 OpenAI 的例外情況（S-05.3）。

### S-05.2 AI 語音播放與輪流控制

| 項目 | 規格 |
| --- | --- |
| 自動播放 | AI 回覆產生後自動播放語音，同時顯示文字 |
| 控制按鈕 | 「停止」：結束播放，直接輪到學生；「重播」：再聽一次 |
| 打斷 | AI 播放中，學生按下「說話」會立即停止播放並開始錄音 |
| 播放時不收音 | AI 播放期間不開麥克風，避免把 AI 的聲音錄成學生發言；播放結束後自動開始聆聽 |
| 開口前 | **不計時**，學生想多久都可以；超過 30 秒只顯示提示「準備好就開始說」 |
| 說話中停頓 | 靜音 3 秒後進入「即將送出」倒數 3 秒，並顯示進度條 |
| 倒數期間 | 學生繼續說話 → 取消倒數，接在同一段發言；「送出」立即送出；「我還沒說完」取消倒數、繼續聆聽 |
| 自動送出開關 | 學生可在設定中關閉自動送出，改成只用按鈕結束 |
| 單次發言上限 | 60 秒 |
| 實作注意 | 部分瀏覽器的語音辨識在靜音後會自行結束，需自動重新開始辨識，避免打斷學生思考 |

### S-05.3「瀏覽器不支援」的判定

**語音辨識**
- 瀏覽器沒有 `SpeechRecognition`（或 `webkitSpeechRecognition`）時，改用 OpenAI。
- 開始辨識後出現 `network`、`service-not-allowed`、`language-not-supported` 錯誤時，也改用 OpenAI，並在這次登入期間持續使用 OpenAI。
- 使用者拒絕麥克風權限（`not-allowed`）**不會**觸發改用 OpenAI，因為改了也一樣無法錄音。此時顯示權限說明，並提供改用文字輸入。

**語音合成**
- 瀏覽器沒有 `speechSynthesis`，或 `getVoices()` 裡找不到中文（`zh-TW`，其次是其他 `zh-*`）語音時，改用 OpenAI。

**語言設定**：辨識語言固定為 `zh-TW`。

## 延伸資料

### S-06.4 來源呈現與無結果／失敗行為

**每筆來源顯示**
- 標題、作者、出版年；
- 來源類型：「教師書單」或「外部資料庫：〈名稱〉」；
- 連結（有的話）。

**防止編造**
- 後端先查教師書單與外部資料庫，把查到的結果（含 ID）交給模型。
- 模型只能引用這些 ID。
- 後端會檢查模型回覆中的引用；不在查詢結果裡的一律刪除，不顯示。
- 模型憑記憶寫出的書目永遠不會出現在畫面上。

**無結果與失敗**

| 情況 | 行為 |
| --- | --- |
| 查無可靠結果 | 顯示「目前找不到可靠的資料」，並建議換個說法；不顯示任何推測的書目 |
| 外部資料庫失敗或逾時（10 秒） | 只顯示教師書單的結果，並註明「外部資料庫暫時無法使用」；兩者都沒有結果時，顯示錯誤與重試按鈕 |
| 查詢面板任何失敗 | 不影響主對話（F-09.3） |

## 非功能需求

### S-10.2 回應時間門檻

測量條件：以 60 人同時使用為負載（S-10.3），數值取 p95（95% 的請求要達標）；頁面載入取 p75。

| 項目 | 門檻 |
| --- | --- |
| 頁面載入（Largest Contentful Paint） | p75 ≤ 2.5 秒 |
| 一般 API（不含 AI） | p95 ≤ 500 毫秒 |
| AI 文字回覆：首個 token | p95 ≤ 5 秒 |
| AI 文字回覆：完整回覆 | p95 ≤ 30 秒 |
| 語音備援：學生說完到出現辨識文字 | p95 ≤ 5 秒 |
| 語音備援：AI 語音開始播放 | 文字回覆完成後 p95 ≤ 3 秒 |

**與 S-03.5 逾時的關係**：本節的門檻是正常狀況下要達到的效能目標；S-03.5 的逾時（首個 token 15 秒、完整回覆 60 秒）是判定「失敗」的界線。例如首個 token 在 8 秒出現，不算失敗，但未達效能目標。

**量測方式**
- 一般 API 的負載測試用假的 AI 實作，以排除 OpenAI 延遲的影響。負載測試工具之後選定，例如 k6。
- AI 相關門檻在測試環境以真實 OpenAI 抽樣量測，每項至少 50 次。
