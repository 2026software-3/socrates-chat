## 帳號與名單

### S-01.4 修課名單匯入與移除

名單以**教室**為單位（S-14）：以下規則都在單一教室內運作；同一學生（同一學號）可同時在多個教室的名單，不影響其他教室。

> 2026-10 修訂：名單加入姓名與學號，學生以學號為識別鍵，匯入不含電子郵件。決定內容見 `decisions.md` 的 S-01.4；該決定由規格 PR #406 合併後生效，本節修訂需與其一併合併。登入與限流見 `S-08.2-auth-verification.md`。

**匯入格式**
- 可上傳 CSV 或文字檔，也可以直接貼上；**每行一位學生，依序為「姓名、學號」兩欄，沒有標題列**，每一行都視為學生資料。
- 姓名與學號必填。匯入前先去除前後空白；學號轉大寫。電子郵件不經匯入，由學生自己填寫。
- 姓名不得為空，長度上限 30 字元；學號為八碼數字加一個英文字母（輸入不分大小寫，儲存與顯示一律大寫）；多出欄位（含舊格式的電子郵件欄）的整行也算格式錯誤。不符的列歸入格式錯誤，不匯入。

**匯入結果**
- 回報新增、已存在（略過）、錯誤的筆數，並列出錯誤的行與原因（缺少欄位、格式不符）。
- 學號已有帳號的列視為已存在，只加入這間教室的名單，不更新任何資料；匯入不設定也不修改電子郵件。
- **姓名以第一次為準**：姓名在建立帳號時寫入，之後的匯入（含其他教室）不更新既有帳號的姓名；同一學號匯入不同姓名時，該列不算錯誤，姓名不變（2026-10 需求方決定）。
- 匯入**只會新增**，不會移除名單上原有但這次檔案沒有的人。移除一律另外操作，避免誤刪。

**移除名單後的資料處理**
- 學生立即失去該教室的學生權限；若不在任何教室名單內，登入後看到「尚未開通」。
- 該教室內的資料**全部保留**；教室的教師仍然看得到他過去的對話總結。
- 重新加回名單後，恢復存取，資料照舊。
- 要真的刪除資料，改用「刪除學生帳號」（F-22.5），或刪除活動／教室（S-14）。

**學號的可見範圍與更正**
- 學號只有該教室的教師、學生本人與管理者看得到（管理者**不遮蔽**，2026-10 需求方決定，S-02.2）；其他教室的教師看不到。日誌、稽核日誌與送往 AI 的請求不含學號。
- 匯入不更新既有學號；輸入錯誤時由教師（限目前在自己教室名單內的學生）或管理者更正，並寫入稽核日誌（操作者、時間、對象帳號的內部識別碼，不保留前後值）；學生下次登入時看到一次站內通知。細節見 `decisions.md` 的 S-01.4。

## 文字對話

本組依一場對話的進行順序排列：怎麼進行（S-03.2）→ 怎麼結束（S-03.3）→ 出錯怎麼處理（S-03.5）。

### S-03.2 追問準則與難度階段

> 本節屬教學設計，授課教師日後可提出調整；調整時同步更新 S-03.4 的評估情境集。

採用三個階段，依序推進，**不會退回前一階段**：

| 階段 | 目標 | 主要追問類型 | 進入下一階段的條件 |
| --- | --- | --- | --- |
| 1. 釐清 | 讓學生說清楚立場 | 澄清：定義關鍵詞、確認立場 | 學生已表達明確立場，並說明關鍵詞的意思 |
| 2. 論證 | 檢視立場背後的理由 | 理由探詢、假設檢視 | 學生至少提出一個理由，且檢視過一個隱含假設 |
| 3. 挑戰 | 測試立場的韌性 | 反例思考、觀點比較 | 學生回應過至少一個反例或對立觀點 → 符合收斂條件（見 S-03.3） |

**每回合的規則**
- 每次只問**一個**問題。
- 不提出 AI 自己的答案或立場。學生問「你覺得呢？」時，改成反問，或平衡列出不同觀點，但不下結論。
- 語氣中立、尊重，不使用侮辱或威脅的表達（F-07.3）。
- 學生離題時，簡短回應後把話題帶回主題。

**實作方式**
- 對話目前在哪個階段，存在後端資料庫，不交給模型自行記憶。
- 每回合請模型以結構化 JSON 回傳：
  - 本回合的追問類型；
  - 是否達到進入下一階段的條件，以及判斷理由。
- 後端依回傳內容更新階段，並把目前階段放進下一回合的提示。
- 這組規則的版本號記錄在每則 AI 回覆上，方便依 S-03.4 做評估與比較。

### S-03.3 對話回合上限

| 項目 | 規格 |
| --- | --- |
| 回合定義 | 學生送出一則訊息算 1 回合 |
| 引導收尾 | 第 15 回合起，AI 開始引導學生整理結論 |
| 上限 | 第 20 回合時，AI 不再追問，直接產生總結並結束對話 |
| 設定方式 | 全系統一個數值，以環境變數設定；不做成每個活動可調 |
| 學生主動結束 | 任何時候都可以 |

### S-03.5 AI 呼叫逾時

| 項目 | 規格 |
| --- | --- |
| 首個 token 逾時 | 15 秒內沒有收到任何串流內容，就視為失敗 |
| 完整回覆上限 | 60 秒；超過就中斷 |
| 自動重試 | 只在**尚未串流出任何內容**時重試 1 次；已經串流到一半才失敗，不自動重試 |
| 串流中途失敗 | 捨棄已產生的部分內容，這則 AI 回覆標記為失敗，顯示「AI 暫時無法回覆」與重試按鈕 |
| 使用者最久等待 | 約 30 秒（15 秒 × 2 次）就會看到錯誤，不會無止盡等待 |

「中途失敗不自動重試」是為了避免同一段回覆在畫面上出現兩次。

推理模型會先串流推理內容、再輸出正文。推理內容也算「串流內容」：收到推理內容就不再套用首個 token 逾時，只受完整回覆上限限制。推理內容不顯示給學生、不保存、不寫入日誌。推理內容不算「已串流出內容」，所以正文出現前失敗仍會自動重試。因此使用推理模型時，最久等待取決於完整回覆上限，不再是上表的約 30 秒。

**備援模型（選用，`OPENAI_FALLBACK_MODELS`）**：供應商對整個模型限流或容量用盡時，依序改用設定的備援模型。

| 項目 | 規格 |
| --- | --- |
| 何時換（HTTP 層） | 主模型的每把 key 都回 429；或主模型的 key 因先前的 429 還在冷卻中（這時不送出請求、也不等待，直接換） |
| 何時換（串流內） | HTTP 已回 200，但**還沒串流出任何內容（正文或推理）**就收到容量錯誤區塊：錯誤碼 429，或訊息含 ResourceExhausted（例如 NVIDIA 的 `Worker local total request limit reached`，以 HTTP 200 加 502 送出）。換模型發生在串流內部，所以呼叫端的首個 token 逾時與完整回覆上限照常涵蓋換模型的時間 |
| 何時不換 | 連線失敗、5xx、401/402/403（key 被拒絕）、其他 4xx、串流內的其他錯誤、已經串流出內容或推理之後的任何失敗（學生已看到部分回覆，不能換成另一個模型的回覆） |
| key 冷卻 | HTTP 429 時每個模型各有獨立的冷卻狀態。主模型的 429 是整個模型的問題，不會讓備援模型拿不到 key。串流內的容量錯誤不冷卻：只代表這一次沒搶到名額，下一個請求仍先試主模型 |
| 順序 | 照設定的先後逐一嘗試；全部都被限流才回「AI 暫時無法回覆」。冷卻結束後，下一個請求會先試回主模型 |
| 範圍 | 對話、總結、評審共用同一個 AI 介面，所以一起套用；沒設定時行為與先前完全相同 |
| 日誌 | 記錄模型名稱與「換模型」的事件，不含 key、對話或提示內容 |

備援模型會改變回覆的品質與風格，換模型期間的回覆不一定與主模型一致；是否啟用、用哪些模型由維運設定。

**每位使用者的 AI 用量上限（暫定，待需求方確認）**：避免任何登入者（包含公開的示範帳號）讓 AI 費用無上限。

| 項目 | 規格 |
| --- | --- |
| 額度 | 每位使用者在 24 小時滑動時間窗內最多 200 次 AI 呼叫（`AI_USAGE_MAX`、`AI_USAGE_WINDOW_SECS`）；所有角色共用同一個額度 |
| 計入 | 使用者按下去才發生的呼叫：對話回覆（含重試）、語音辨識與合成、教師翻譯總結、教師重新分組 |
| 不計入 | 對話結束後自動產生的總結與主張分組（受回合上限約束）；瀏覽器內建的 Web Speech 與 `Translator` |
| 失敗 | 沒有得到結果的呼叫會退回額度，AI 當機時的重試不會把使用者鎖在外面 |
| 用完 | 對話回覆的 SSE 以 `error` 事件 `ai_usage_exceeded` 結束（學生訊息已保存，額度回復後可重試）；語音與教師功能回 429 `ai_usage_exceeded` |
| 顯示 | `GET /api/me/usage` 回傳 `used`、`limit`、`window_secs`、`resets_in_secs`；前端在外框顯示用量 |
| 限制 | 計數放在記憶體，重啟後歸零，多個實例各自計算（部署方式未定案，S-09） |

## 語音

本組先寫正常流程（S-05.2），再寫改用 OpenAI 的例外情況（S-05.3）。

### S-05.2 AI 語音播放與輪流控制

| 項目 | 規格 |
| --- | --- |
| 自動播放 | AI 回覆產生後自動播放語音，同時顯示文字 |
| 控制按鈕 | 「停止」：結束播放，直接輪到學生；「重播」：再聽一次 |
| 打斷 | AI 播放中，學生按下「說話」或直接開口，會立即停止播放並開始錄音（開口打斷見 [S-05.5](S-05.5-audio-processing.md)，預設關閉，學生可開啟） |
| 播放時不辨識 | AI 播放期間辨識器不運作，避免把 AI 的聲音錄成學生發言；麥克風只在瀏覽器內偵測開口，音訊不上傳；播放結束後自動開始聆聽 |
| 開口前 | **不計時**，學生想多久都可以；超過 30 秒只顯示提示「準備好就開始說」 |
| 說話中停頓 | 靜音 3 秒後進入「即將送出」倒數 3 秒，並顯示進度條 |
| 倒數期間 | 學生繼續說話 → 取消倒數，接在同一段發言；「送出」立即送出；「我還沒說完」取消倒數、繼續聆聽 |
| 自動送出開關 | 學生可在設定中關閉自動送出，改成只用按鈕結束 |
| 單次發言上限 | 60 秒 |
| 實作注意 | 部分瀏覽器的語音辨識在靜音後會自行結束，需自動重新開始辨識，避免打斷學生思考 |

### S-05.3「瀏覽器不支援」的判定

**語音辨識**
- 瀏覽器沒有 `SpeechRecognition`（或 `webkitSpeechRecognition`）時，改用 OpenAI。
- 開始辨識後出現 `network`、`service-not-allowed`、`language-not-supported` 錯誤時，也改用 OpenAI，並在這次登入期間持續使用 OpenAI。
- 使用者拒絕麥克風權限（`not-allowed`）**不會**觸發改用 OpenAI，因為改了也一樣無法錄音。此時顯示權限說明，並提供改用文字輸入。

**語音合成**
- 瀏覽器沒有 `speechSynthesis`，或 `getVoices()` 裡找不到對話語言的語音時，改用 OpenAI。找語音的順序：完全相符的地區（見下表），其次是同語言的其他地區（例如 `zh-*`）。

**語言設定**：辨識與合成語言跟隨該場對話的語言（S-12.1）：

| 對話語言 | 語音語言 |
| --- | --- |
| `zh-TW` | `zh-TW` |
| `en` | `en-US` |
| `es` | `es-ES` |

## 延伸資料

### S-06.4 來源呈現與無結果／失敗行為

**每筆來源顯示**
- 標題、作者、出版年；
- 來源類型：「教師書單」或「外部資料庫：〈名稱〉」；
- 連結（有的話）。

**防止編造**
- 後端先查教師書單與外部資料庫，把查到的結果（含 ID）交給模型。
- 模型只能引用這些 ID。
- 後端會檢查模型回覆中的引用；不在查詢結果裡的一律刪除，不顯示。
- 模型憑記憶寫出的書目永遠不會出現在畫面上。

**無結果與失敗**

| 情況 | 行為 |
| --- | --- |
| 查無可靠結果 | 顯示「目前找不到可靠的資料」，並建議換個說法；不顯示任何推測的書目 |
| 外部資料庫失敗或逾時（10 秒） | 只顯示教師書單的結果，並註明「外部資料庫暫時無法使用」；兩者都沒有結果時，顯示錯誤與重試按鈕 |
| 查詢面板任何失敗 | 不影響主對話（F-09.3） |

## 多語言

### S-12.1 支援語言與語言設定

| 項目 | 規則 |
| --- | --- |
| 支援語言 | `zh-TW`、`en`、`es`；預設 `zh-TW` |
| 語言設定來源 | 使用者資料表的語言欄位；首次登入由 `Accept-Language` 比對（取第一個支援的語言，無則 `zh-TW`），之後以使用者設定為準 |
| 介面文字 | 全部走翻譯資源檔；三種語言鍵值必須一致，CI 檢查缺漏 |
| 後端錯誤 | 回傳 `{ code, request_id }`，不含已翻譯文字；前端以 `code` 查翻譯 |
| 對話語言 | 開始對話時複製使用者的語言設定到該場對話，進行中不變；之後切換語言只影響新的對話與介面 |
| AI 提示 | 每種語言各有提示與規則，版本記錄含語言（例如 `v1/zh-TW`）；系統提示指示 AI 只用對話語言回覆 |
| AI 行為評測 | `zh-TW`、`en`、`es` 各一套語意對等的情境，共用相同評分準則；結果依提示版本與語言分開記錄 |
| AI 總結 | 以對話語言產生 |
| 教師閱讀總結 | 預設顯示原文；教師可明確觸發按需翻譯，且翻譯不取代原文。先使用瀏覽器內建 `Translator` API；不存在、不支援該語言配對、下載或翻譯失敗時，才由後端把 `stance`、`reasons` 送給 AI。目標為教師帳號語言；結果只留在目前頁面，不保存或快取 |
| 格式 | 日期、數字依語言設定格式化 |
| `message` 遮蔽 | 固定字串，不翻譯 |

**Given / When / Then**
- Given 新使用者瀏覽器偏好 `es-MX`，When 首次登入，Then 語言設定為 `es`。
- Given 瀏覽器偏好 `fr`，When 首次登入，Then 語言設定為 `zh-TW`。
- Given 學生語言設定為 `en` 並開始對話，When 之後切換為 `es`，Then 該場對話的 AI 仍以英文回覆，新對話以西班牙文進行。
- Given 任一語言的翻譯檔缺少某個鍵值，When 執行 CI，Then 檢查失敗。
- Given 管理者查看任何語言的對話，When 顯示訊息內容，Then 一律顯示 `message`。

## 非功能需求

### S-10.2 回應時間門檻

測量條件：以 60 人同時使用為負載（S-10.3），數值取 p95（95% 的請求要達標）；頁面載入取 p75。

| 項目 | 門檻 |
| --- | --- |
| 頁面載入（Largest Contentful Paint） | p75 ≤ 2.5 秒 |
| 一般 API（不含 AI） | p95 ≤ 500 毫秒 |
| AI 文字回覆：首個 token | p95 ≤ 5 秒 |
| AI 文字回覆：完整回覆 | p95 ≤ 30 秒 |
| 語音備援：學生說完到出現辨識文字 | p95 ≤ 5 秒 |
| 語音備援：AI 語音開始播放 | 文字回覆完成後 p95 ≤ 3 秒 |

**與 S-03.5 逾時的關係**：本節的門檻是正常狀況下要達到的效能目標；S-03.5 的逾時（首個 token 15 秒、完整回覆 60 秒）是判定「失敗」的界線。例如首個 token 在 8 秒出現，不算失敗，但未達效能目標。

**量測方式**
- 一般 API 的負載測試用假的 AI 實作，以排除 OpenAI 延遲的影響。負載測試工具之後選定，例如 k6。
- AI 相關門檻在測試環境以真實 OpenAI 抽樣量測，每項至少 50 次。
