# Whisper 語音辨識效能紀錄（base、small）

試用自架 Whisper（base，後補 small 對照）取代 OpenAI 語音辨識的量測紀錄（2026-10-26）。**這是量測結果，不是規格決策**：具體採用哪個辨識模型仍在 `open-decisions.md`，未定案。

## 環境

- GPU：NVIDIA GeForce RTX 4050 Laptop（6 GB），WSL2；無任何負載時已佔 221 MiB（顯示用，下表「增量」已扣除）
- faster-whisper 1.2.1（CTranslate2 4.8.4），模型 `base`（約 74M 參數），beam_size 5，指定語言
- 測試音檔為合成語音（edge-tts 產生，不含真實學生資料）：中、英各一段 4 秒與一段約 55 秒
- 後端接法：`OPENAI_STT_BASE_URL=http://127.0.0.1:8000/v1`、`OPENAI_STT_MODEL=whisper-base`，服務見 `scripts/whisper-server.py`

| 設定 | 載入後增量 | 辨識時尖峰增量（長音檔 55 秒） | 載入時間 | 主機 RAM |
| --- | --- | --- | --- | --- |
| GPU float16 | 約 273 MiB | 約 387 MiB | 1.2 s | 約 820 MiB |
| GPU int8_float16 | 約 209 MiB | 約 291 MiB | 0.7 s | 約 820 MiB |

經 HTTP 服務、8 路並行時整體尖峰約 640 MiB（含 221 MiB 底噪），顯存幾乎不隨並行數成長。

## 辨識品質（僅供參考，樣本很小）

- 英文兩段逐字正確。
- 中文短句正確；長句有專有詞錯誤：「未經檢視」被辨成「為金箭式」（float16）、「為經檢室」（int8_float16）。哲學術語密度高的課堂內容可能需要更大的模型（small／medium），或在提示詞（`initial_prompt`）帶入術語；要正式採用前應用真實錄音評估。
- int8_float16 省約 25% 顯存、速度相同，但同一段長句的錯誤略不同，沒有明顯變好或變差。

## 結論

- Whisper base 在這張 6 GB 顯卡上只佔約 0.3–0.4 GB，GPU 與對話服務（資源上限見 `docker-compose.ntnu.yml`）不衝突；CPU int8 也夠快（長音檔 RTF 約 0.04），沒有 GPU 時可行。
- 瓶頸不在顯存而在序列化：並行請求排隊，8 人同時送 1 分鐘長錄音要等約 12 秒；一般短句（數秒）幾乎無感。
- 服務以 `WHISPER_PERF_LOG` 可逐請求記錄耗時與 GPU 使用量（不含辨識文字），可用來收集真實使用時的數據。

## Whisper small 對照（2026-10-26 補測）

同一台機器、同一組音檔與量測方式，模型換成 `small`（約 244M 參數）。

| GPU int8_float16 | 約 369 MiB | 約 579 MiB | 1.6 s | 約 840 MiB |

| --- | --- | --- | --- |

| 中文 57.6 s | 1.67 s（0.029） | 1.75 s（0.030） | 5.15 s（0.089） |

| 英文 54.8 s | 1.31 s（0.024） | 1.33 s（0.024） | 4.07 s（0.074） |

### 中文術語辨識

測試句「蘇格拉底說未經檢視的人生不值得活」（長音檔中重複 3 次）：

| 模型 | 辨識結果（3 次皆相同） | 錯字 |
| --- | --- | --- |
| base float16 | 蘇格拉底說**為金箭式**的人生不值得活 | 4 |
| small float16 | 蘇格拉底說**為**經檢視的人生不值得活 | 1（「未」→「為」） |
| small int8_float16 | 同 small float16 | 1 |
| small CPU int8 | 蘇格拉底說未經檢視的人生不值得活（全對） | 0 |

其餘句子（含標點）三者皆正確；4 秒短句 base 與 small 都正確。樣本只有一個術語，CPU int8 全對可能是量化帶來的偶然差異，不能據此說 CPU 比 GPU 準。

### base 與 small 比較

- **顯存**：small float16 約為 base 的 2.2 倍（尖峰 835 vs 387 MiB）；small int8_float16（579 MiB）仍比 base float16 多約 50%。6 GB 顯卡都放得下。
- **速度**：GPU 上 small 約慢 1.5 倍（長音檔 1.7 s vs 1.05 s），仍遠快於即時；CPU 上慢 2.4 倍（5.2 s vs 2.2 s），短句約 1 秒。
- **術語**：small 明顯較好（錯 1 字 vs 4 字），但仍非全對。
- **量化**：small 用 int8_float16 省約 30% 顯存、速度幾乎相同、辨識結果與 float16 一致，是 GPU 上的合理預設。

### 更新後的結論

若要自架，建議以 small 為起點：GPU 的 int8_float16 約 0.6 GB、長音檔 RTF 0.03，術語辨識優於 base，成本仍很小。是否採用 small 仍需用真實課堂錄音（口音、雜音、術語密度）評估，並確認 Whisper 的授權與部署方式；這份紀錄不構成規格決策。

## 用 initial_prompt 帶入課堂術語（2026-10-26 補測）

`scripts/whisper-server.py` 新增 `WHISPER_INITIAL_PROMPT`（預設為哲學術語清單：蘇格拉底、柏拉圖、產婆術、未經檢視的人生、無知之知、德爾菲神諭、詰問法、美德即知識），請求帶 OpenAI 的 `prompt` 欄位時以請求為準；另加 `WHISPER_VAD`（預設開）。

### 測試設計

- 6 個含術語的中文句子 × 3 種台灣中文合成音色（edge-tts）＝ 18 段，GPU float16，beam_size 5。
- 字錯率（CER）：去掉標點與空白後的 Levenshtein 距離／參考字數。術語命中：句中出現的 8 個術語，辨識結果有幾個完全正確。
- 另用 8 秒純靜音與 8 秒粉紅雜訊檢查是否幻聽。
- **限制**：提示詞裡的術語就是測試句用到的術語（等於考試範圍洩漏），所以這裡量到的是「清單內的術語」能改善多少，不代表沒列出的詞也會變好。語音是合成的，6 句、一個領域，樣本很小。

### 結果

| 模型／設定 | CER | 整句全對 | 術語命中 | 靜音／雜訊 |
| --- | --- | --- | --- | --- |
| base，無 prompt | 10.7% | 1／18 | 13／33 | 皆空 |
| base，有 prompt | 5.2% | 2／18 | 27／33 | 雜訊吐出部分 prompt |
| small，無 prompt | 15.7% | 1／18 | 13／33 | 雜訊幻聽「字幕by索兰娅」 |
| small，有 prompt | 2.7% | 8／18 | 29／33 | **靜音、雜訊都整段吐出 prompt** |
| small，有 prompt ＋ VAD | 2.7% | 8／18 | 29／33 | 皆空 |

- **術語**：prompt 讓兩個模型的術語命中率都從 13／33 升到 27–29／33；small 的 CER 從 15.7% 降到 2.7%。
- **為何 small 無 prompt 反而比 base 差**：small 有 5 段輸出簡體字，全被算成錯字；prompt 使用繁體寫法後，輸出幾乎都變回繁體。prompt 同時決定了字體偏好，這對台灣使用情境是額外好處。
- **幻聽風險**：有 prompt 時，靜音或雜訊錄音會讓 small 把整段提示詞當成辨識結果。學生按了錄音卻沒說話，就會送出一串術語，所以**帶 prompt 時必須同時開 VAD**。服務預設兩者並用。
- **VAD 的影響**：開 VAD 後靜音與雜訊回空字串，18 段語音的 CER 與命中數完全不變；前後各加 5 秒靜音、語音疊 0.6 倍粉紅雜訊的兩個情境也都辨識正確。
- **仍會錯的**：「詰問」被辨成「結婚」「結問」（提示詞是「詰問法」，沒用）；「明知是壞事」被辨成「明知識壞事」（受「美德即知識」影響，是 prompt 帶來的新錯誤）；「站得住腳」偶爾變「站得住角」。
- **速度**：經 HTTP 服務，small float16 開 VAD 與 prompt 後，4 秒短句 0.24 s，57 秒長音檔 1.83 s，與先前（無 prompt）相近。

### 結論與建議

1. 要用 small，建議 `WHISPER_MODEL=small`、`WHISPER_COMPUTE=int8_float16`、保留預設 prompt 與 VAD。
2. prompt 只對清單內的術語有效，且有長度限制（Whisper 只取最後約 224 個 token），也會造成「明知是」這類被術語帶偏的錯誤。術語清單應由教師依活動題目維護，不要塞太多；後端目前不送 `prompt`，若要依活動帶入術語，需另開 Issue 討論。
3. 這份結果仍是合成語音。要採用前，用真實課堂錄音比較有無 prompt 的字錯率，並確認被帶偏的詞（如「明知識」）不會比被修好的詞多。

## 以 Common Voice zh-TW 真人錄音驗證（2026-10-26 補測）

前面的結果全是合成語音。這裡改用真人朗讀的 Common Voice，檢查 prompt＋VAD 對一般句子是否有副作用。

### 資料與方法

- 資料：Common Voice Corpus 19.0 zh-TW 的 `test` split（5013 句、1224 位說話者），取自社群鏡像 [JacobLinCool/common_voice_19_0_zh-TW](https://huggingface.co/datasets/JacobLinCool/common_voice_19_0_zh-TW)（CC0）；官方 `mozilla-foundation` 的 Hugging Face 資料集已於 2025 年 10 月下架。
- 抽樣：每位說話者隨機取 1 句，再取 200 句（隨機種子 0）；共 1627 字、763 秒（平均約 3.8 秒）。
- 音檔只放在暫存目錄，**未進 repo**；本文件只保留統計數字。
- GPU float16、beam_size 5、指定中文。CER 與前一節同算法（去標點與空白）。「轉繁體後 CER」是把輸出先以 OpenCC（s2t）轉成繁體再算，用來排除簡繁字體差異。
- 「prompt 洩漏」：輸出含提示詞術語、但參考句沒有的句數。

### 結果（200 句）

| 模型／設定 | CER | 轉繁體後 CER | prompt 洩漏 | 輸出為空 |
| --- | --- | --- | --- | --- |
| base，無 prompt | 26.8% | 24.2% | 0 | 1 |
| base，prompt＋VAD | 23.7% | 23.8% | 4 | 0 |
| small，無 prompt | 20.2% | 15.6% | 0 | 0 |
| small，prompt＋VAD | 14.2% | 14.4% | 1 | 0 |

### 解讀

- **CER 偏高是資料的特性**：句子短、錄音設備與環境不一、同音字多（如「樂星人」「熱心人」）、參考句的寫法（數字、標點）與輸出不一致。這些數字用來比較設定，不要拿去和公開的 Whisper 成績比。Whisper 也可能在訓練中看過 Common Voice，絕對值可能偏樂觀。
- **prompt 的進步大多來自字體**：不轉繁體時 small 從 20.2% 降到 14.2%，但轉繁體後只剩 15.6% → 14.4%（差約 1 個百分點，約 18 個字），base 幾乎沒差（24.2% → 23.8%）。沒有 prompt 時 small 常輸出簡體字；帶繁體 prompt 後多數改回繁體。扣掉字體後，prompt 對一般句子沒有明顯幫助，但也沒有明顯傷害。200 句的樣本差異這麼小，不足以下結論。
- **洩漏在真人短句上真的發生**：base 4 句、small 1 句把提示詞當辨識結果，例如「直奔富士山」被辨成「詰問法、美德即知識。」，「巴士終於來了」被辨成「法、詰問法、詰問法、美德即知識。」。這發生在開了 VAD 的情況下，所以 VAD 能擋掉靜音與雜訊，擋不住「有聲音但很短或不清楚」的錄音。small 的洩漏率較低（0.5%）但不是零。
- **VAD 沒有濾掉語音**：small 沒有任何一句被濾空；base 無 prompt 時有 1 句本來就輸出為空。

### 對建議的修正

前一節的建議（small＋int8_float16＋預設 prompt＋VAD）仍可用，但要補上：

1. 預設 prompt 會偶爾整段出現在輸出中，辨識結果不應直接當作學生的發言存檔而不經處理。可行的緩解：在服務端比對輸出與提示詞，若輸出幾乎全是提示詞內的詞，就視為無有效語音而回空字串（尚未實作，也未測試）。
2. 若不需要術語偏好，只想要繁體輸出，可以只給很短的繁體提示（例如一句繁體中文句子），洩漏風險較低；這同樣沒有測過。
3. 要依活動題目帶術語時，應該用真實課堂錄音另測洩漏率，不要只看術語命中率。

## 提示詞洩漏過濾（2026-10-26 實作）

針對上一節發現的洩漏，`scripts/whisper_echo.py` 的 `is_prompt_echo()` 在服務端把「幾乎全是提示詞內的詞」的輸出改成空字串（效能記錄多一欄 `prompt_echo_dropped`）。

### 規則

先去掉標點與空白，再同時符合兩個條件才丟掉：

1. **涵蓋率 ≥ 90%**：輸出中至少 90% 的字，落在「也出現在提示詞裡、長度至少 2 字的連續片段」內。
2. **有洩漏特徵**：原文含頓號「、」，或有重複的片段（長度至少 2 字）。

只用條件 1 會誤殺學生真的說出的「蘇格拉底說未經檢視的人生」（涵蓋率 92%），所以加了條件 2：模型吐出提示詞時幾乎都帶頓號或重複，一般口說的句子不會。單獨一個術語（例如只回答「產婆術」）也不會被丟掉。

### 驗證

單元測試 `scripts/test_whisper_echo.py`（`python3 scripts/test_whisper_echo.py`），6 項通過：

| 輸入 | 結果 |
| --- | --- |
| 整段提示詞 | 丟掉 |
| Common Voice 實測吐出的 4 種輸出：「法、詰問法、詰問法、美德即知識。」「蘇格拉底、菲神諭、美德即知識」「即知識知識。」「詰問法、美德即知識。」 | 全部丟掉 |
| 空字串、單一術語、「蘇格拉底說未經檢視的人生」、其他 4 句一般中文句子 | 全部保留 |
| 沒有提示詞 | 一律保留 |

端到端（small float16，經 HTTP 服務）：

| 輸入 | 關閉 VAD（模型自己吐出提示詞） | 開啟 VAD |
| --- | --- | --- |
| 8 秒靜音 | 丟掉，回 `""` | `""` |
| 8 秒雜訊 | 丟掉，回 `""` | `""` |
| 3 句含術語的合成語音 | 原樣保留 | 原樣保留 |

### 限制

- **沒有用原始音檔重現**：Common Voice 19.0 的音檔在量測後已刪除，27.0 尚未下載，所以洩漏案例是用當時記錄下來的輸出「文字」測試，不是重新跑音檔。等 27.0 取得後，應重跑一次，確認洩漏句確實被丟掉、且沒有誤殺正常句。
- **抓不到混雜亂碼的洩漏**：實測中有一句輸出「免領大派、領域、術品、美德路。」，只有一小部分是提示詞內的詞（涵蓋率約 18%），不會被丟掉；測試把這點明確記為已知限制。
- **會誤殺只念術語的清單**：學生若只念「蘇格拉底、柏拉圖」這種用頓號隔開的術語，會被當成洩漏而得到空字串。實際對話中很少見，空結果時前端應提示重說或改用文字輸入。
- **過濾的是結果，不是原因**：洩漏仍會發生，只是被擋下。未洩漏但被提示詞帶偏的錯字（如「明知識」）不受影響。

## 以 Common Voice 27.0 zh-TW 官方資料重測（2026-10-26）

上面「Common Voice zh-TW」一節用的是 19.0 的第三方鏡像；官方資料集已搬到 [Mozilla Data Collective](https://mozilladatacollective.com/datasets/cmu5wkw5i00c6o107jnm3t51u)，條款禁止重新託管、並要求不得辨識說話者。這一節改用官方下載的 **Common Voice Scripted Speech 27.0 zh-TW**（cv-corpus-27.0-2026-09-11，CC0-1.0，約 14.1 萬段錄音）。音檔只放在暫存目錄，未進 repo，文件只記統計數字。

### 資料與方法

- 取 `test.tsv`（5137 句、1269 位說話者），每位說話者隨機取 1 句，再取 200 句（隨機種子 0）；共 1613 字、795 秒（平均約 4 秒）。
- 其餘方法與 19.0 一節相同（GPU float16、beam_size 5、指定中文、CER 去標點空白、「轉繁體後」用 OpenCC s2t）。
- 同設定重跑會有約 ±0.3 個百分點的浮動（例如 base 無 prompt 兩次為 29.6% 與 29.8%），所以小於 1 個百分點的差異不要當成結論。
- 27.0 比 19.0 新很多，Whisper 的訓練資料較不可能涵蓋，絕對值應比 19.0 更可信。

### 結果（200 句）：分開看 VAD 與 prompt

| 模型／設定 | CER | 轉繁體後 CER | prompt 洩漏 | 輸出為空 |
| --- | --- | --- | --- | --- |
| base，無 prompt | 29.8% | 27.5% | 0 | 0 |
| base，只開 VAD | 29.6% | 27.8% | 0 | 0 |
| base，只用 prompt | 25.1% | 25.6% | 3 | 1 |
| base，prompt＋VAD | 25.2% | 25.9% | 1 | 3 |
| small，無 prompt | 17.6% | 14.7% | 0 | 0 |
| small，只開 VAD | 15.9% | 15.0% | 0 | 0 |
| small，只用 prompt | 15.9% | 16.6% | 2 | 2 |
| small，prompt＋VAD | 15.6% | 16.1% | 0 | 1 |

### 解讀

- **prompt 對一般句子沒有穩定的好處**：扣掉簡繁差異後，small 從 14.7% 變成 16.1–16.6%（變差），base 從 27.5% 變成 25.6–25.9%（變好）。加上 19.0 的結果（small 變好、base 持平），三組方向不一致，看起來是雜訊而不是效果。
- **prompt 會讓短句消失**：輸出為空的句子全部出現在有 prompt 的設定，沒有 prompt 時為 0；被吃掉的是 2–3 秒的短句（例如「補個眠」「林業鐵路」），而且 VAD 單獨使用時不會發生，所以原因是 prompt 本身，不是 VAD。蘇格拉底式對話裡學生常常只回答一兩個字，這個副作用值得注意。
- **VAD 能降低洩漏**：只用 prompt 時洩漏 base 3 句、small 2 句；再開 VAD 降到 1 句、0 句。VAD 單獨使用也沒有把任何語音濾空。
- **洩漏過濾器（`whisper_echo.py`）在這批資料上沒有動作**：prompt＋VAD 的輸出中沒有任何一句被丟掉。small 沒有洩漏；base 唯一一句洩漏是「即知識識。要不要繼續。」，混有正常內容而且只有一部分是提示詞，涵蓋率不到 90%，依設計不會被丟掉。也就是說，過濾器沒有誤殺任何一句，但這次也沒有機會證明它能抓到真人錄音的洩漏；它抓洩漏的證據仍然只有 19.0 時記錄下來的輸出文字與合成的靜音、雜訊。

### 對建議的修正

1. 預設 prompt 的好處（術語偏好、輸出繁體）只在含術語的句子上有證據，對一般句子沒有穩定的好處，還會讓短句變空。**不要預設為所有請求都帶 prompt**；只在活動題目有術語、且確實需要時才帶，並用真實課堂錄音確認。
2. 若只想要繁體輸出，可以改為對輸出做簡轉繁（例如 OpenCC），不必靠 prompt；這同樣還沒實作。
3. VAD 建議保留：它降低洩漏，也沒有濾掉語音。
4. 輸出為空時，前端應提示重說或改用文字輸入；後端可考慮對空結果再用不帶 prompt 的設定重試一次（未實作、未測試）。
