# 規格決策紀錄

需求方於 2026-09-29 確認的規格決策。每項對應一張規格 sub-issue（`S-xx.n`）；「部分決定」的項目列出仍待決定的內容。
尚未決定的事項不得在實作中自行假設，請先在對應的規格 Issue 討論。

## 產品範圍前提

- 系統只服務**一門課程**：沒有班級，也不分學期。所有活動、對話與統計都屬於同一個課程。
- **使用資格**：教師或管理者匯入修課名單（學生電子郵件）；名單外的帳號登入後看到「尚未開通」。
- **角色**：學生、教師（可多位，含助教，權限相同）、系統管理者。
- **登入**：只接受 Google。

## S-01 確認登入、角色核發與修課名單規則

### S-01.1 身分服務與 OAuth 整合方式（已決定）

- 由 Rust 自行整合 Google OAuth；session 存於 PostgreSQL，以 HttpOnly cookie 傳遞。
- 只接受 Google 登入，不提供其他登入方式。

### S-01.2 帳號識別規則（已決定）

- 一個 Google 帳號對應一個使用者，以 Google 帳號 ID 識別。
- 電子郵件用於比對修課名單；不做帳號連結。

### S-01.3 角色核發、權限矩陣與管理者／停用流程（部分決定）

- 預設角色為學生（需在修課名單內）。
- 使用者可自行申請教師身分，由管理者審核後生效；教師可有多位（含助教），權限相同。
- 首位管理者由部署時的環境變數（例如 `ADMIN_EMAILS`）指定，這些信箱首次登入即成為管理者。
- **仍待決定**：帳號停用／復原流程

### S-01.4 修課名單規則（部分決定）

- 系統只服務一門課程，沒有班級，也不分學期；原班級邀請機制作廢。
- 教師或管理者匯入學生電子郵件名單；名單外帳號登入後看到「尚未開通」。
- **仍待決定**：匯入格式、移除名單後該學生資料的處理方式

## S-02 確認個資可見範圍、去識別化與資料生命週期

### S-02.1 角色 × 資料可見矩陣（已決定）

- 教師可查看所有修課學生已完成對話的 AI 總結與學生反思，**不能看對話原文**。
- 應用程式的管理介面、API、報表、匯出與日誌中，訊息以 `message` 顯示。
- 系統管理者可直接存取資料庫與備份，因此讀得到原文；需在隱私說明中告知學生，且資料庫存取需留紀錄。

### S-02.2 敏感欄位清單與 `message` 替代規則（已決定）

- 敏感欄位：對話訊息、AI 總結、學生反思、分析結果（雷達圖、標籤、邏輯樹）、語音逐字稿；管理者介面一律遮蔽，訊息以 `message` 顯示。
- 管理者看得到姓名與電子郵件（管理帳號需要）；日誌連電子郵件也不記錄。

### S-02.3 雷達圖／個人檔案公開規則（已決定）

- 個人整體雷達圖預設不公開；公開後課程內所有人（修課學生與教師）可見。
- 公開時顯示角色外觀與顯示名稱，不顯示電子郵件等其他個資；題目統計等不隨之公開。

### S-02.4 課程彙整與研究輸出的去識別化與門檻（部分決定）

- 論點分布不設最小群體門檻，且只給教師看。
- **仍待決定**：研究輸出的用途與欄位

### S-02.5 保存、刪除、備份與續談政策（已決定）

- 對話紀錄保留到帳號刪除；學生可自行刪除單場對話。
- 刪除帳號時一併刪除對話與分析結果；備份中的資料依備份週期自然淡出。

## S-03 確認 AI 服務供應商、對話、追問難度與收斂評估規格

### S-03.1 AI 服務供應商與模型選型（部分決定）

- 先採用 OpenAI；後端將 AI 呼叫包成單一介面，保留更換供應商的彈性。
- **仍待決定**：具體模型（依 S-03.4 評估）

### S-03.3 收斂條件、總結欄位與人工修正（部分決定）

- 學生隨時可主動結束。
- AI 在學生已說明立場與理由、且回應過至少一個反例或對立觀點時提議收尾；另設回合上限。
- AI 總結不可修改；學生可另外附加「我的反思」。
- **仍待決定**：回合上限的數值

### S-03.4 AI 行為評分準則與情境集（已決定）

- 固定情境集＋另一個模型依評分準則自動評分（每次修改提示都執行）＋教師團隊定期人工抽查。

### S-03.5 外部 AI 服務失敗行為（部分決定）

- 學生訊息先存入資料庫；AI 逾時或錯誤時自動重試 1 次，仍失敗則顯示「AI 暫時無法回覆」與重試按鈕，訊息不遺失。
- **仍待決定**：逾時秒數

## S-04 確認個人分析結果、雷達圖與思辨視覺化規格

### S-04.2 雷達圖哲學派系維度與計分（部分決定）

- 先採 6 個常見倫理學派系作為維度：效益主義、義務論、德行倫理、契約論、關懷倫理、存在主義；之後可調整。
- **仍待決定**：各派系的定義與計分方式

## S-05 確認語音互動模式與音訊處理方式

### S-05.1 語音輸入確認流程（已決定）

- 辨識文字填入輸入框，學生可在送出前編輯，確認後才送出。

### S-05.2 輪流對話回合與播放控制（部分決定）

- 瀏覽器端偵測靜音自動結束這一輪發言，也可手動按鈕結束；輪流模式以 HTTP 傳輸即可。
- **仍待決定**：AI 語音的播放、停止與中斷方式細節

### S-05.3 語音服務選型與資料流（部分決定）

- 混合：預設使用瀏覽器 Web Speech API；不支援時改用 OpenAI 語音 API（經 Rust）。
- 瀏覽器模式的逐字稿由前端回傳後端保存；需在隱私說明中告知音訊會送往瀏覽器廠商。
- **仍待決定**：「瀏覽器不支援」的判定方式

## S-06 確認 AI 題目／資料查詢／閱讀推薦的資料來源

### S-06.3 書目來源與推薦品質準則（部分決定）

- 優先使用教師維護的書單；不足時查外部書目資料庫，並標示來源；不得編造書目。
- **仍待決定**：外部書目資料庫的選擇

## S-07 確認角色素材與遊戲化規則

### S-07.5 是否納入教材觀看獎勵（已決定）

- 本期不納入教師指定教材觀看獎勵（F-19.5 為草稿 issue）。

## S-08 確認前後端、PostgreSQL 與 AI 服務的責任邊界

### S-08.1 元件關係圖與資料流（已決定）

- 前端與 API 部署在同一個網域（API 走 `/api`），session cookie 為第一方 `SameSite=Lax`。
- 後端模組化；AI 呼叫一律經 `AiProvider` 介面；管理者輸出在序列化層統一遮蔽；錯誤統一為 JSON 並附 request ID。
- 語音備援的 TTS 也經後端代理，前端不接觸 OpenAI。
- 詳見 [`S-08.1-component-dataflow.md`](S-08.1-component-dataflow.md)。

### S-08.2 登入憑證驗證與身分映射（部分決定）

- Google OIDC Authorization Code + PKCE（`openidconnect` crate），驗證 state、nonce、ID token 簽章與 `email_verified`。
- 以 Google `sub` 識別使用者；角色每次請求從資料庫載入；教師與管理者不需在修課名單內。
- Session：256 位元隨機 token，資料庫只存雜湊；cookie 為 HttpOnly、Secure、SameSite=Lax；閒置 7 天失效、絕對上限 30 天；CSRF 以 `Origin` 檢查。
- 不限制 Google 帳號網域，由修課名單把關。
- 詳見 [`S-08.2-auth-verification.md`](S-08.2-auth-verification.md)。
- **仍待決定**：教師申請是否需要填寫資料

### S-08.3 連線池、migration 工具與設定管理（已決定）

- migration 使用 `sqlx migrate`（`backend/migrations/`）。
- 設定與秘密一律用環境變數；本機用 `.env`（不進版控），並提供 `.env.example`。

### S-08.4 對話 API 傳輸方式與錯誤邊界（已決定）

- 對話 API 採 HTTP + SSE 串流；若語音日後需要即時串流，再加 WebSocket。

## S-09 確認 PostgreSQL 部署與維運責任

### S-09.1 各環境部署方式（部分決定）

- 開發與 CI 使用 Docker Compose 的 PostgreSQL。
- **仍待決定**：正式環境的部署方式（託管或自架）

### S-09.2 憑證與網路存取（部分決定）

- 憑證由部署平台的秘密管理（或 GitHub Actions secrets）注入環境變數；不進版控、不進前端；資料庫不對公網開放。
- **仍待決定**：具體平台（隨正式環境決定）

### S-09.3 migration、監控、備份還原流程與負責人（部分決定）

- Migration 只往前、採「先擴充、後收縮」；正式環境部署前單獨執行 `sqlx migrate run`；CI 加上 `cargo sqlx prepare --check`。
- 監控：`/health` 存活、`/ready` 檢查資料庫；JSON 日誌不含敏感內容；列出告警條件。
- 備份：每日 `pg_dump` 並以公鑰加密，保留 7 份每日＋4 份每週；私鑰離線保存，由 2 位指定的系統管理者各持一份，解密與還原都留紀錄。
- RPO 24 小時、RTO 4 小時；還原演練每 6 個月一次，並在上線前做一次。
- 詳見 [`S-09.3-ops-procedures.md`](S-09.3-ops-procedures.md)。
- **仍待決定**：維運負責人與備援負責人的人選

## S-10 確認瀏覽器支援、效能與負載驗收門檻

### S-10.1 瀏覽器支援清單（已決定）

- 支援 Chrome、Edge、Safari（含 iOS）、Firefox 各最新 2 個主要版本；Firefox 的語音辨識改走 OpenAI。

### S-10.3 同時使用人數與負載測試方法（已決定）

- 同時使用人數約 60 人（全班同時上課對話）；負載測試以此設計。
