# S-19 語音節點登錄

> **狀態：已決定（2026-11-22），後端已實作（2026-11-24）；管理介面與 NTNU 的實際切換未做。** 沒有需求方 Issue：開發者依使用者委派，對下列取捨自行決定，決定過程見 `decisions.md` 的 S-19。其中標示「暫定」「未驗證」的數字不是驗收條件。

## 1. 目標與範圍

讓新設備**不重啟後端**就能加入伺服器端語音服務（[cascade-voice-spike.md](cascade-voice-spike.md)）。

- **目標**：管理者新增、暫停、移除語音節點，後端即時依節點健康與負載分配新的語音場次。
- **只做語音節點**。節點是 cascade 整組（VAD、ASR、TTS、轉接層）所在的設備，硬體不限（NVIDIA 容器或 macOS 原生皆可），規格只看下一節的契約。
- **不做**（各項理由見第 8 節）：管理介面、節點自行註冊、對話途中換節點、只提供 TTS 或只提供 ASR 的節點、多個後端實例、Redis。

## 2. 節點契約（與硬體無關）

一個節點必須提供：

| 項目 | 要求 |
| --- | --- |
| 即時端點 | `ws://` 或 `wss://` 的 `/v1/realtime`（cascade）；主機必須是內網位址或內部主機名稱（見 7.1） |
| 健康端點 | 同主機同埠的 `/health`，由即時端點 URL 推得（`ws→http`、`wss→https`、路徑換成 `/health`）。回 2xx 視為健康 |
| 回呼位址 | 節點的 cascade 以 `launch.yaml` 的 LLM 節點呼叫後端內部端點；位址是**節點自己的設定**，不存在登錄表 |
| 密鑰 | 登錄時產生的節點密鑰，節點以環境變數 `CASCADE_LLM_TOKEN` 帶給 cascade |
| 版本 | `sglang-omni==0.2.0` 並套用 `docker/cascade/patch_dialog.py`（對不上時 cascade 不會啟動，見 cascade-voice-spike） |

`/health` 通過不代表 TTS 或轉接層仍活著；真正失效時由第 5 節的連線失敗處理接住。

## 3. 資料模型

新增 migration（檔名用實作當天的日期；NTNU 為正式環境，只往前，見 S-09.3）。表 `voice_nodes`：

| 欄位 | 規格 |
| --- | --- |
| `id` | uuid 主鍵 |
| `name` | 唯一，管理者命名，日誌與稽核只用它或 `id` |
| `realtime_url` | 只允許 `ws`、`wss` 兩種 scheme（資料庫 CHECK 加後端驗證） |
| `token_hash` | `bytea`，唯一；存 SHA-256，不存明文 |
| `max_sessions` | 整數，≥ 1，**必填**；建議起始值 1（暫定，未驗證） |
| `status` | `active`／`draining`／`disabled` |
| `created_at`、`updated_at` | 時間戳 |

健康狀態與場次數**不存資料庫**：健康是探測結果，場次數在記憶體，重啟後自然歸零。

同一個 migration 要擴充 `audit_logs_action_check`（既有做法見 `20261112000000_audit_change_password.sql`：讀出現有規則，再 `OR` 加上新動作），加入 `voice_node_create`、`voice_node_update`、`voice_node_rotate_token`、`voice_node_delete`。沒有這一步，稽核寫入會被資料庫拒絕。

## 4. 環境節點

既有的 `CASCADE_REALTIME_URL` 與 `CASCADE_LLM_TOKEN` 兩個環境變數**繼續有效**，視為一個固定存在的「環境節點」：

- 兩者都設了才存在（沿用現行規則）。
- **永遠留在可選池中**，不是「登錄表為空時才用」。否則加入第一個遠端節點，就會悄悄讓 NTNU 本機的 GPU 退出輪替。
- **預設不設場次上限**，以免登錄表出現前後行為改變；可用選填的 `CASCADE_MAX_SESSIONS` 設上限。
- 不在資料庫、不能由管理 API 修改或刪除。管理 API 的列表以固定識別字串 `env` 表示它。
- 登錄表為空且未設環境變數時，行為等同現在的「未啟用」。
- **與現行行為只有一處刻意的差異**：`voice_realtime` 改為看節點健康（見 5.1），而不是「環境變數設了就是真」。每個節點在程序啟動時**先視為健康**，直到探測失敗才降級，所以重啟後不會有 10 秒語音被隱藏。除此之外，只設環境變數時的行為與現在相同。

## 5. 選節點

### 5.1 規則

學生開啟 `GET /api/conversations/{id}/voice` 時：

1. 候選＝環境節點加 `active` 的登錄節點，且健康、場次數小於上限。
2. 取場次數最少者；相同時環境節點優先，其次依 `name`。
3. **選擇與場次數加一在同一把 `VoiceSessions` 鎖內完成**，不可先選後加，否則併發會超過上限。
4. 場次記下綁定的節點；`VoiceSession` 釋放時一併減少。
5. 沒有候選就回 `503 voice_unavailable`（前端本來就會改用瀏覽器語音）。

`voice_realtime`（對話詳情）為真的條件：存在至少一個 `active` 且健康的節點，**不看是否已滿**。全滿時進入 `/voice` 才回 503。

### 5.2 連線失敗的重試

`relay` 在 WebSocket 升級**之後**才連節點，連不上時學生會看到失敗。因此：

- 連節點失敗（`connect_async` 錯誤或逾時）時，**立即把該節點標為不健康**，換下一個候選**重試一次**（同一規則、排除已失敗者，並把場次改綁新節點）。
- **每次連線嘗試的逾時為 3 秒**（暫定）。瀏覽器 10 秒沒有回應就視為 `unreachable`（前端行為），兩次嘗試加 `session.update` 必須放得進這個時間；不設逾時時，不可達的私網位址會用掉整個視窗。
- 仍失敗才結束，瀏覽器收到 `unreachable` 並改用瀏覽器語音。
- 這使「剛加入但其實壞掉」的節點對學生無害。

### 5.3 不做對話途中轉移

節點在場次進行中失效時，沿用現行行為：關閉原因為 `lost`，這一輪標成可重試，學生重新按「即時」時再依 5.1 選一次。

## 6. 健康探測

- 背景工作每 10 秒對每個 `active` 與 `draining` 節點打健康端點，逾時 3 秒（暫定）。
- 連續 3 次失敗標為不健康；一次成功即恢復。第 5.2 節的連線失敗立即標為不健康，不必等 3 次。
- 探測結果與**節點清單**（用於選節點與列表）都在記憶體，節點清單以 2 秒 TTL 從資料庫重讀（仿 `MaintenanceFlag`），資料庫讀不到時沿用上一次的值。
- **密鑰驗證不走這個快取**：內部端點每次都直接以雜湊查資料庫（一次索引讀取），所以輪換與停用立即生效，不會被快取延遲。快取只影響第 7.2 節的場次結束時間。
- 探測不記日誌內容；失敗只記節點 `id` 與原因類別。

## 7. 管理 API 與安全

### 7.1 管理 API（僅系統管理者）

| 方法與路徑 | 作用 |
| --- | --- |
| `GET /api/admin/voice-nodes` | 列出（含環境節點，標示不可改）。每筆含 `status`、健康、目前場次數、`max_sessions`、`realtime_url` |
| `POST /api/admin/voice-nodes` | 新增。回應**僅此一次**含明文 `token`（32 隨機位元組，十六進位） |
| `PATCH /api/admin/voice-nodes/{id}` | 改 `name`、`realtime_url`、`max_sessions`、`status` |
| `POST /api/admin/voice-nodes/{id}/rotate-token` | 換新密鑰，舊的立即失效；回應僅此一次含明文 |
| `DELETE /api/admin/voice-nodes/{id}` | 移除 |

- **`realtime_url` 的主機只能是內網**（新增與 `PATCH` 都檢查，2026-11-26）。只判斷寫法，**不做 DNS 解析**：
  - IP 允許：迴路（`127.0.0.0/8`、`::1`）、私有（`10/8`、`172.16/12`、`192.168/16`）、link-local（`169.254/16`、`fe80::/10`）、CGNAT（`100.64/10`，tailnet 位址）、IPv6 ULA（`fc00::/7`）。其餘（公開 IP、`0.0.0.0`、多播）一律拒絕。`134744072` 這類十進位寫法會先被正規化成 `8.8.8.8`，因此同樣被拒。
  - 主機名稱允許：沒有點的單一標籤（例如 compose 服務名 `cascade`），或以 `.internal`、`.local`、`.lan`、`.localdomain`、`.ts.net`（tailnet MagicDNS）結尾。其他網域（例如 `example.com`）拒絕。
  - 不符回 400，錯誤碼 `realtime_url_not_internal`（格式本身不是 `ws://`／`wss://` 仍是 `invalid_realtime_url`）。
  - 目的：管理者填的網址會被後端主動探測與連線，不限制就成了從後端內網對任意位址發請求的通道（SSRF）。
  - 檢查只擋「寫法」：內部後綴的名稱若被 DNS 指到公開位址，不會被擋；後綴清單與 `100.64/10` 納入 tailnet 屬暫定，需求方確認前不視為定案。
- `realtime_url` 不是秘密，管理者看得到；`token` 只在建立與輪換時回傳一次，之後任何回應都不含。
- 全部要 `#[utoipa::path]`，並寫稽核日誌：只記操作者、動作、節點 `id` 與 `name`，**不記 URL 與 token**。
- 錯誤回應照全站格式，不含內部資訊。

### 7.2 暫停與撤銷

| 狀態 | 新場次 | 進行中的場次 | 密鑰 |
| --- | --- | --- | --- |
| `active` | 接收 | 正常 | 有效 |
| `draining` | 不接收 | 繼續到結束 | 有效 |
| `disabled`／刪除 | 不接收 | **最慢一個快取週期（2 秒）內結束**（關閉該節點的 relay） | **立即失效**（每次直接查資料庫，見第 6 節） |

`draining` 用於正常下線；`disabled` 或刪除用於節點遭入侵或必須立刻切斷。

### 7.3 節點密鑰

- 每節點一把，與環境節點的密鑰各自獨立。
- 驗證方式：對收到的 Bearer 取 SHA-256，以雜湊查表（高熵隨機值，不需要 Argon2；內部端點每一輪都會呼叫，慢雜湊只增加延遲）。環境節點的密鑰沿用現行的常數時間比對。
- **綁定檢查**：`/internal/cascade/v1/chat/completions` 除了驗密鑰，還要確認「這把密鑰屬於的節點」等於「這個一次性場次代號綁定的節點」，不符就拒絕。一個被入侵的節點因此不能代操其他節點的場次。
- `/internal/cascade/v1/models` 是 cascade 啟動時的探測，沒有場次代號：只驗密鑰屬於某個有效節點（含環境節點），不做綁定檢查。

### 7.4 內部端點的網路隔離

現況：`/internal/cascade/` 與公開路由在同一個埠，NTNU 的 funnel 直接指向該埠，S-16 的代理也不在路徑上，所以這個端點目前可從網際網路打到，只靠 Bearer。遠端節點要回呼它，不能再靠「在代理擋掉」。

- 新增選填環境變數 `INTERNAL_LISTEN_ADDR`（例如 `0.0.0.0:3001`）。
  - **設定時**：`/internal/cascade/*` 從公開 router 移除（公開埠回 404），改由獨立的監聽器提供。部署方只把這個埠開在私網（例如 tailnet 的 `tailscale serve`，**不是 funnel**）。
  - **未設定時**：行為與現在完全相同。
  - **設定後，NTNU 本機的 cascade 也要改**：它現在以 `http://app:3000/internal/cascade/v1` 做每一輪的呼叫與啟動探測，公開埠回 404 之後這兩者都會失敗。所以啟用這個變數的同一次部署，必須把本機 cascade 的回呼改指向內部埠（`launch.yaml` 樣板化，加上不對主機公開的 compose 埠）。只設變數而不改 cascade 的回呼，語音會整個壞掉；部署文件要把兩者寫成一組步驟。
- 遠端節點的回呼位址指向這個私網位址；各自的 `launch.yaml` 回呼位址要能設定。`docker/cascade/launch.yaml` 的 `http://app:3000/internal/cascade/v1` 與 `scripts/cascade-macos/render_launch.py` 對這個字串的精確比對**要一起改**（macOS 腳本在 `feat/macos-cascade` 分支，尚未進 main，由該分支處理）。
- 學生音訊走 `ws://` 是明文：遠端節點的 `realtime_url` 必須在私網（tailnet 之類的加密網路）內，否則用 `wss://`。後端只強制「主機在內網」（7.1），不強制加密；內網不等於加密，明文與否由部署方負責，這點寫入 `docs/ntnu-ops.md`。
- tailnet 的具體設定步驟寫在 `docs/ntnu-ops.md`，不寫在本規格。

## 8. 不做的事

| 項目 | 理由 |
| --- | --- |
| 管理介面 | 本期只做 API；API 穩定後另開 |
| 節點自行註冊 | 需要一個公開的啟動密鑰與另一個對外端點；由管理者新增已算「熱加入」 |
| 對話途中換節點 | cascade 狀態無法搬移，沿用「可重試」 |
| 只含 TTS 或只含 ASR 的節點 | 轉接層雖已分開轉送，但跨機器延遲未量過 |
| 多個後端實例 | `VoiceSessions`、`LiveReplies`、`UserLimiter`、`KeyPool`、`SpeechSlots` 都在單一程序記憶體；本規格假設只有一個後端實例 |
| Redis | 本規格需要的資料都是低頻的，Postgres 與記憶體快取足夠 |

## 9. 測試要求

以下情境各要有測試，且先確認因正確的理由失敗（AGENTS.md）：

- **選節點**：最少場次者優先、滿載跳過、`draining` 不接新場、全不可用回 503、相同場次時環境節點優先。
- **環境節點相容**：只設環境變數時行為與現在相同（唯一差異是 `voice_realtime` 看健康，且節點啟動時先視為健康）；加入登錄節點後環境節點仍在池中；`CASCADE_MAX_SESSIONS` 未設時不限。
- **併發**：同時開啟多場不超過任一節點的 `max_sessions`（選與加一在同一把鎖內）。
- **重試**：第一個節點連線失敗時改用第二個並標記第一個不健康；兩個都失敗才結束；重試不使場次數洩漏。
- **健康探測**：健康端點回 2xx、5xx、逾時；連續 3 次失敗才降級；一次成功即恢復。
- **授權**：未登入、學生、教師呼叫管理 API 都被拒；只有管理者可用。
- **節點網址限制**：私有、迴路、link-local、CGNAT、ULA 的 IP 與內部主機名稱可新增；公開 IP、公開網域、`0.0.0.0`、多播、十進位寫法的公開位址被拒（`realtime_url_not_internal`）；`PATCH` 改成公開網址同樣被拒。
- **內部端點**：錯誤密鑰、已輪換的舊密鑰、`disabled` 或已刪除節點的密鑰、屬於**另一個節點**的密鑰（綁定檢查）都被拒；`INTERNAL_LISTEN_ADDR` 設定時公開埠對 `/internal/cascade/*` 回 404。
- **撤銷**：輪換或停用後，**立刻**以舊密鑰呼叫內部端點就被拒（不等快取）；`disabled` 與刪除在一個快取週期內結束該節點的場次。
- **稽核**：四個新動作都能寫入 `audit_logs`（約束已擴充）。
- **逾時**：不可達的節點在 3 秒內失敗，兩次嘗試加起來小於前端的 10 秒視窗。
- **隱私**：token 與 `realtime_url` 不出現在日誌與稽核紀錄；`token` 只在建立與輪換的回應出現。
- **回歸**：既有的 `cascade.rs`、`cascade_e2e.rs`、`cascade_drop_log.rs` 測試不改就通過。

## 10. 未驗證與待確認

- `max_sessions` 預設值 1、健康探測間隔與逾時、連續失敗次數都是暫定值，沒有量測依據。
- Kokoro 單節點多人容量未驗證（cascade-voice-spike 的「容量」）。
- 回呼走私網位址、`INTERNAL_LISTEN_ADDR` 加 `tailscale serve` 的路徑尚未在 NTNU 實測；NTNU 的 `docker-compose.ntnu.yml` 不進版控，部署時要人為處理。
- `/health` 與 TTS、轉接層實際可用性的落差，只靠 5.2 的重試補償。
- 內部端點分離監聽器會改變公開 router 的組成，需評估對 `lib.rs` 中介層（維護模式、Origin 檢查）的影響。
