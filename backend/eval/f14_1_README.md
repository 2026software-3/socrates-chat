# F-14.1 推薦品質評估

對應 #81 與 S-06.3。合成情境位於 `f14_1_cases.json`。推薦規則版本為 `book-recommendations-v2/<對話語言>`，評估程式版本為 `f14.1-eval-v2`。

繁體中文、英文和西班牙文各有八個情境，涵蓋公平與責任、立場歸屬、短對話、外部查詢門檻、空書庫提出具體書籍、僅憑書名、明確改變觀點，以及只能讀取總結。每個情境用正式流程的提示與 JSON 契約。評分檢查相關性、忠於學生表達與可得書目資料、思考題是否開放、語言是否一致，以及該情境特有的要求。五項都通過才算該情境通過，評分不依賴固定措辭。

在 `backend/` 執行。

```bash
cargo test --lib evaluation_cases_build_production_requests_in_each_language
cargo test --lib live_book_recommendation_evaluation -- --ignored --nocapture
```

第一個指令驗證 24 組正式格式的輸入及長對話退回總結的路徑。第二個指令使用已設定的 `OPENAI_MODEL`、不同的 `EVAL_JUDGE_MODEL` 與現有本機評估憑證。兩個模型都會使用 API 額度。輸出包含情境、版本與各項評分；可加 `CASE=title_only` 只評估該情境的三個語言版本。

## 實作邊界

每次最多交給模型 40 部作品，依適用教師書單、其餘近期啟用的共用作品排序。每部挑一個符合語言的版本提供精簡資料；結果包含候選中所有符合語言的啟用版本。模型輸入以 48,000 UTF-8 bytes 為上限，超限時改帶題目和原有總結。AI 最多提出五組具體書名及作者，逐本 Google Books 優先，無可用結果才查 Open Library。每本每個來源的總預算為十秒，Google 最多五筆，Open Library 最多三筆版本並查核各版本第一位作者的紀錄。書名、作者以忽略大小寫及標點空白後的一致性比對，不猜譯名或作者別名；因此不同譯名、缺作者或其他未能對應的版本可能查無。查核後才讓 AI 判斷相關性與產生理由，呈現欄位採用來源資料。書目查詢僅含限長的書名及作者，攔截既有遮蔽規則可辨識的個資、佔位詞、網址及控制字元；無法藉此保證辨識所有自由文字中的個人經歷，模型亦受不得複製個人內容的提示約束。

上線前已成功的總結可由學生首次手動觸發推薦。啟動時會將未完成的推薦標記為中斷，等待學生手動重試。

## 本輪驗證

v2 的固定情境、推薦 API 與來源測試使用合成資料與測試替身，檢查先提具體書籍再查核、同名異作者／衍生書／缺作者排除、個資攔截與部分查無。真實模型評估待提供獨立評分模型；離線結果只驗證輸入與程式契約。Google Books 資料的持久保存相容性仍待確認。

2026-11-22 本機驗證：`cargo fmt --check` 與 `cargo clippy --all-targets -- -D warnings` 通過。受 VM 磁碟限制，完整測試改為逐一執行 `cargo test --lib`、`--bins`、每個 `--test <target>` 及 `--doc`，均帶 `-- --test-threads=1`。共 1,221 個案例通過、2 個真實模型測試忽略，包含 20 個推薦整合測試、13 個書目來源測試及 24 組三語輸入契約。初次全套編譯因磁碟不足中斷，清理舊重複測試執行檔後改為逐目標執行；其中既有的 40ms Open Library 預算測試曾在搜尋送達前逾時，單獨重跑及整組 13 個來源測試重跑皆通過，未修改該測試或生產逾時設定。這些結果不等同真實模型推薦品質已驗證。
